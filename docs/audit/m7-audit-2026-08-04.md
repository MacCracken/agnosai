# M7 sandbox audit — 2026-08-04

**43 confirmed findings across the eight sandbox modules.** Every one survived an
adversarial verifier that applied the stated mutation and re-ran the suite; four
further claims were refuted and are not listed.

The suite was green throughout — 65 suites, 4,372 assertions, 100% reference
coverage. That is the point of this document: reference coverage counts whether a
symbol is *named* by a test, not whether any assertion would *fail* without it.

## Method

One auditor per module, each asked the same primary question — **"for each
load-bearing line, if I deleted or inverted it, would any assertion fail, and
which one?"** — seeded with the five vacuous-test patterns this port has already
shipped:

- asserting an error message `contains "error:"` when every message is prefixed
  `"sandbox error: "`, so deleting an entire exit-code check still passed
- asserting `contains "0"` on a uid, which matches `1000`
- asserting output is blanked on timeout with a payload that produced no output
- a landing test that only exercised `resolve_backend()` while claiming to cover
  dispatch
- a probe testing `fd >= 0` where cx compares unsigned, so `-EACCES` read as
  success

Each finding then went to a verifier instructed to **refute** it, defaulting to
false, and required to show the command output it saw. Verifiers backed up and
restored every file they touched; the tree was confirmed clean afterwards.

## Status

**43 fixed, 0 open** as of 2026-08-05. Every entry is marked `✅ FIXED` in
place, and **every fix was mutation-verified**: the stated mutation was applied
to a working tree, the suite rebuilt and re-run, and the failing assertion
named. The tree was restored and confirmed clean after each.

Sandbox suites, before → after: policy 90 → **102**, oci 100 → **118**,
kavach_bridge 93 → **136**, spawn 144 → **169**, process 108 → **130**, python
61 → **76**, manager 69 → **90**, cx 62 → **87**. That is **627 assertions
against 727**, +100 — and the spawn suite runs in **10 s where it took 32.6 s**,
because the 30-second sleep that finding H5 showed was measuring nothing is
gone.

## Two fixes that no test can hold up, said plainly

**L5** (`sakshi_warn` called with a hardcoded length one byte short) and **L9**
(the manager's missing dispatch `debug!`) are both log-only. Nothing in this
tree captures sakshi output, and L5's branch is unreachable in practice —
kavach accepts `RUNNING -> STOPPED` unconditionally. Both fixes are correct and
both mutants **survive**: reverting L5 to `sakshi_warn(..., 43)` leaves the
suite at 136/136. They are recorded here rather than quietly counted as
verified, because "43 fixed" would otherwise imply 43 killed mutants and the
number is 41.

## What the fix order looked like in the end

- **Every live crash/leak defect is closed** — the SIGPIPE pair (H1, H7) and
  `spawn`'s leaking `_agnosai_spawn_failure()` early returns (M10) went with the
  three descriptor defects fixed on 2026-08-04.
- **Every deletable security control now has an assertion that dies with it** —
  `kavach_bridge`'s `strlen`-vs-`str_len` scan (H2), `spawn`'s inherited-env
  sanitizer (H4) and `FD_CLOEXEC` call site (H5), `process`'s loader-injection
  filter (H6), and cx's network isolation (H10). Two of those were fixed by
  making the control *reachable from a test* — the env filters now take their
  source block as a parameter, so the question stops depending on whether the
  machine running the tests happens to export an `LD_*`.
- **cx's skip guards are real everywhere** (H9), and
  `agnosai_cx_interpreter_path` can answer "not installed" again (M22), which
  also closes the cwd-plant vector that came with it.
- **Both fail-open divergences are closed.** The manager's 0-second default is
  now a deadline that fires at once rather than none at all (M17) — including
  down the OCI arm, where the seconds conversion would otherwise have restored
  it a layer lower — and `policy`'s parser refuses negative durations and sizes
  (M1), which reached kavach as `timeout_ms: -1000` and armed nothing.
- **The vacuous-assertion backlog is worked**, 25 findings. The recurring shape
  was not a missing assertion but an *unreachable* one: five fixes worked by
  splitting a function so the thing under test could be handed its input
  (`_agnosai_sanitized_envp_of`, `_agnosai_process_envp_from`,
  `_agnosai_cx_resolve_interpreter`, `_agnosai_cx_budget_ms`,
  `_agnosai_sandbox_manager_timeout_ms`), and two more by re-execing the suite
  through its own spawn primitive with a planted `envp`, which is the only way a
  process with no `setenv` can put a variable in its own environment.

Nothing left in this document crashes, leaks, lets a security control be deleted
silently, or fails open.

**A fix is not done until its mutation fails a test.** Two tests written during
remediation asserted nothing on the first attempt — one used `dir_open`/
`dir_read`, which do not exist, so the calls were DCE'd and it reported green.
Apply the mutation, run the suite, confirm the failure.

## Fix order

1. **Live defects** (crash / leak) — these are not test gaps.
2. **Deletable security controls** — the confinement is real but nothing holds it in place.
3. **Fail-open divergences.**
4. **Vacuous assertions.**

## HIGH (10)

### ✅ FIXED — H1. [`oci`] execute() drops the oracle's stdin-write error handling — a runtime that exits without draining stdin kills the whole process with SIGPIPE

**Evidence.** Confirmed by direct probe. Built a .tcyr calling agnosai_oci_config_set_runtime(c, "/bin/true") with a 1,280,000-byte input, then agnosai_oci_execute(...) followed by println("SURVIVED"). Output: `input bytes: / 1280000` then `EXIT=141` — 128+13 = SIGPIPE. "SURVIVED" never printed, assert_summary never reached. Adding `signal_ignore(SIGPIPE);` (lib/syscalls.cyr:104) as the only change made the identical probe print `SURVIVED` / `1 passed, 0 failed` / `EXIT=0`, proving the signal is the cause. `grep -rn -i "sigpipe|SIG_IGN|rt_sigaction|sigaction" src/ tests/` returns ZERO hits, so the divergence is neither handled nor documented anywhere in agnosai — the auditor's undocumented claim holds. src/sandbox/spawn.cyr:545-548 confirms the write is `var w = sys_write(iwf, idata + isent, want); if (w > 0) { isent = isent + w; moved = 1; }` — a negative return is silently treated as EAGAIN, so -EPIPE is indistinguishable from backpressure. The oracle (rust-old/src/sandbox/oci.rs:158-162) does `if let Some(mut stdin) = child.stdin.take() && let Err(e) = stdin.write_all(...) { warn!(...) }` — log and continue — and Rust std installs SIG_IGN for SIGPIPE at startup, so the oracle cannot die here. Production is masked only incidentally: the only SIG_IGN in the process comes from _sandhi_server_ignore_sigpipe() inside sandhi's serve loops (lib/sandhi.cyr:13557 etc.), so nothing protects tests, benchmarks, or a consumer that textually includes src/sandbox/mod.cyr without running a sandhi server. Blast radius is wider than oci: the same primitive is used at src/sandbox/process.cyr:327 and :360, src/sandbox/python.cyr:141, and src/sandbox/cx.cyr:193.

**Fix.** Call `signal_ignore(SIGPIPE)` (lib/syscalls.cyr:104) once before the fork in `agnosai_spawn_capture_input`, and change spawn.cyr:545-548 to distinguish -EPIPE from -EAGAIN — on EPIPE close `iwf`, set `iopen = 0`, and `sakshi_warn("failed to write to container stdin")`, matching oci.rs:161.

### ✅ FIXED — H2. [`kavach_bridge`] scan_output hands the gate a raw pointer, so the scan length is strlen() not str_len() — secrets after an embedded NUL are released as PASS

**Evidence.** Confirmed by code and by a live probe. lib/kavach.cyr gate_apply: `var total = strlen(stdout) + strlen(stderr);` and `_concat_with_nl(a,b)` does `strlen(a)` — the Str length is never available to it. src/sandbox/kavach_bridge.cyr:192 passes `str_data(output)` (lib/str.cyr:71, a bare borrowed pointer; str_new/str_substr do NOT NUL-terminate — lib/str.cyr:42-53, 634-640). Probe output verbatim:
  nul-embedded verdict: 0
  space verdict:        3
  substr len:           10
  substr verdict:       3
  literal 10b verdict:  0
So (a) str_new(buf,23) = "ok\0AKIAIOSFODNN7EXAMPLE" returns PASS(0) while the identical 23 bytes with a space returns BLOCK(3) — under-scan releasing a credential; (b) str_substr(str_from("clean-part|AKIAIOSFODNN7EXAMPLE"),0,10) — 10 clean bytes — returns BLOCK(3) while the same 10 bytes as a literal returns PASS(0) — over-read past the Str. Oracle rust-old/src/sandbox/kavach_bridge.rs:159 passes `stdout: output.to_string()`, a length-carrying String, so Rust scans all 23 bytes and returns Block. Nothing in the module header (lines 1-64, which documents every other divergence in detail) mentions NUL-termination. Line 122 `config_agent_id(c, str_data(agent_id))` has the same defect (lib/kavach.cyr:3459 stores the pointer verbatim); line 327 correctly uses `str_cstr(command)`. Every test input is `str_from("literal")`, so no assertion can observe either half.

**Fix.** Use `str_cstr(output)` at :192 and `str_cstr(agent_id)` at :122 to kill the over-read, and either reject embedded NULs in scan_output or file kavach for a length-carrying `gate_apply` — str_cstr alone still lets strlen truncate at an interior NUL.

### ✅ FIXED — H3. [`spawn`] Child never closes irf/owf/ewf after dup2 — leaked pipe copies pin the parent for the whole timeout

**Evidence.** CONFIRMED, measured both directions. Probe (unmodified tree, /home/macro/Repos/agnosai/src/sandbox/spawn.cyr:484-491): the exec'd child's /proc/self/fd prints `0 1 2 3 4 6 8` — fds 3 (irf), 6 (owf), 8 (ewf) are leaked dups (4 is `ls`'s own dirfd). Timings on the unmodified tree: `(exec 0<&- 1>&- 2>&-; sleep 4) & echo detached` = 4014 ms; `sleep 4 >/dev/null 2>&1 </dev/null & echo backgrounded` = 4009 ms. Adding `sys_close(irf); sys_close(owf); sys_close(ewf);` after line 491: fd listing becomes `0 1 2 3`, the two probes return in 16 ms and 10 ms. Full suite with that fix: still 144 passed / 0 failed — no assertion moves, so the defect is invisible to tests/sandbox_spawn.tcyr. One auditor claim is wrong and I downgrade nothing for it: spawn.cyr:628 does NOT hardcode AGNOSAI_SPAWN_NO_TIMEOUT (timeout_ms is a forwarded parameter) and no shipped caller uses NO_TIMEOUT — python.cyr:141, cx.cyr:193, process.cyr:327/360, oci.cyr:358 all pass a real deadline, so the stall is bounded, not unbounded. Severity stays high because the trigger is not exotic daemonization: the ordinary `cmd >file 2>&1 &` idiom stalls for the full configured timeout and is then reported as timed_out with output blanked, where tokio's wait_with_output returns immediately (silent oracle divergence, undocumented).

**Fix.** In the child, after `sys_close(xrf);` (spawn.cyr:491) close the originals — `if (irf > 2) { sys_close(irf); } if (owf > 2) { sys_close(owf); } if (ewf > 2) { sys_close(ewf); }` — and add a test asserting a background-with-redirect child returns in well under its deadline.

### ✅ FIXED — H7. [`python`] Non-empty stdin + a child that exits early kills the calling process with SIGPIPE instead of returning an error

**Evidence.** Reproduced directly. Probe calling agnosai_python_execute_script(sandbox_with_config("/nonexistent/python3",5000), "pass", <320000-byte Str>, &e) printed only "payload bytes: 320000" and never reached the post-call print; shell reported exit=141 on 3/3 runs (128+13 = SIGPIPE). Same with a real interpreter: sandbox_with_config("python3") running "import sys; sys.exit(0)" with the same 320000-byte input -> exit=141, 3/3. Shrinking the payload to 32000 bytes makes both calls return normally (exit_code=0, exit=0, 3/3), confirming the ~64 KiB pipe-buffer threshold. Mechanism confirmed in src/sandbox/spawn.cyr:544-548: `var w = sys_write(iwf, ...); if (w > 0) { isent = isent + w; moved = 1; }` -- every negative return is treated as EAGAIN, there is no EPIPE arm, and `grep -rn 'SIGPIPE|SIG_IGN|rt_sigaction' /home/macro/Repos/agnosai/src/` returns zero hits (only lib/sandhi.cyr:13352-13369 installs SIG_IGN, and only inside its own serve loop). **Fix.** In spawn.cyr's write loop, detect -EPIPE (-32) distinctly from EAGAIN: close iwf, set iopen=0, and record a stdin-write failure that agnosai_python_execute_script surfaces as the oracle's `failed to write to python stdin` error; optionally also install SIG_IGN for SIGPIPE at agnosai init.

### ✅ FIXED — M1. [`policy`] from_value accepts negative max_duration_secs/max_memory_bytes; -1 reaches kavach as "no deadline"

**Evidence.** Confirmed by probe built against the real tree (no repo modification): `agnosai_sandbox_policy_from_json("{\"max_duration_secs\":-1,\"max_memory_bytes\":-1}")` returns a non-zero policy with `duration: -1`, `memory: -1`, and `agnosai_kavach_build_config(neg,0)` yields `kavach timeout_ms: -1000`. src/sandbox/policy.cyr:266-272 guards only on `bayan_json_v_is_int`, never on range. src/sandbox/kavach_bridge.cyr:121 does `agnosai_sandbox_policy_max_duration_secs(policy) * 1000` with no guard, and lib/kavach.cyr:8354 arms the deadline only under `if (timeout_ms > 0) { deadline = mono_now_ns()/1000000 + timeout_ms; }` — so a negative timeout arms NO deadline. The auditor's claim that manager.cyr is safe by luck also checks out: `_agnosai_sandbox_manager_timeout_secs` (src/sandbox/manager.cyr:178) guards `> 0` and falls back to the manager default. MITIGATION the auditor missed: `grep -rn "policy_from_value\|policy_from_json" src/` returns ZERO hits outside policy.cyr itself — no production path currently feeds attacker data into this parser, so the hole is latent rather than live. That is why I rate this medium, not high.

**Fix.** Clamp both fields in `agnosai_sandbox_policy_from_value` — treat `dur < 0` and `mem < 0` as out-of-domain and fall back to the default (matching serde's u64/usize refusal), and add a `if (secs > 0)` guard on the multiply at src/sandbox/kavach_bridge.cyr:121 as defence in depth.

### ✅ FIXED — M3. [`policy`] The _a allocator arguments are never verified — to_value_a/to_json_a can discard the arena and every assertion still passes
